PROJECT QUESTION
How does mutation rate affect the ability of different phylogenomic methods to recover a known evolutionary tree from Aevol 4b genomes?

The project uses Aevol 4b to simulate ATGC genomes under an explicit evolutionary model, then tests whether phylogenomic methods can recover the known simulated 16-tip species tree. The initial simulation phase produced final tip FASTA files. The next analysis phase prepared those FASTAs for phylogenetic inference, inferred trees with several methods, and scored inferred trees against the known true tree.


HIGH-LEVEL WORKFLOW THAT WAS BUILT

1. Simulation scaffold
   The project scaffold was built under aevol_phylo_mutrate with separate config, script, data, run, and results folders. The scaffold supports:

   - one shared pre-evolved ancestor
   - one known balanced 16-tip species tree
   - five mutation-rate regimes
   - one replicate so far: rep_001
   - collection of one final FASTA per species tip
   - QC of final FASTA files

2. Mutation-rate regimes
   Five local sequence-level mutation-rate regimes were defined:

   - very_low: 0.0625x baseline
   - low: 0.25x baseline
   - normal: 1.0x baseline
   - high: 4.0x baseline
   - very_high: 16.0x baseline

   Only these Aevol parameters were scaled:

   - POINT_MUTATION_RATE
   - SMALL_INSERTION_RATE
   - SMALL_DELETION_RATE

   Large rearrangement parameters were left unchanged from the baseline parameter file.

   The resolved parameter table is:

   - data/manifests/mutation_params_resolved.tsv

3. True species tree
   A balanced 16-tip species tree was generated and used as the known ground truth for all mutation-rate regimes.

   Important files:

   - data/true_trees/true_tree_16tips.nwk
   - data/manifests/tree_edges.tsv

   The tree manifest contains 30 branches/edges, as expected for a fully bifurcating 16-tip tree with 15 internal nodes.

4. Aevol simulation outputs
   Aevol produced final genomes for all five mutation-rate regimes in rep_001. The final raw FASTA outputs were frozen as the raw input source for phylogenetic work.

   Important folders:

   - data/raw_final_fastas/very_low/rep_001/
   - data/raw_final_fastas/low/rep_001/
   - data/raw_final_fastas/normal/rep_001/
   - data/raw_final_fastas/high/rep_001/
   - data/raw_final_fastas/very_high/rep_001/

   Each condition has:

   - S01.fa through S16.fa
   - all_tips.fa

5. FASTA cleaning and phylogeny input preparation
   The raw final FASTAs were cleaned into standardized phylogeny inputs with simple tip names S01 through S16.

   Important folders:

   - data/clean_fastas/very_low/rep_001/
   - data/clean_fastas/low/rep_001/
   - data/clean_fastas/normal/rep_001/
   - data/clean_fastas/high/rep_001/
   - data/clean_fastas/very_high/rep_001/

   Each cleaned condition has:

   - all_tips.clean.fa
   - sample_manifest.tsv

PHYLOGENETIC METHODS THAT WERE RUN

Three main tree-building methods were implemented/tested for rep_001:

1. mash_bionj
   Workflow:
   - use Mash to estimate pairwise genome distances from cleaned FASTA inputs
   - convert Mash output to a square distance matrix
   - use R ape::bionj to infer a tree

   Main script:
   - scripts/08_run_mash_bionj.sh

   Outputs are under:
   - results/phylo/mash_bionj/{condition}/rep_001/

   Typical files:
   - mash_distances.tsv
   - distance_long.tsv
   - distance_matrix.tsv
   - inferred_tree.nwk
   - run.log

2. mafft_iqtree
   Workflow:
   - align all 16 cleaned tip genomes using MAFFT
   - summarize alignment properties
   - infer a maximum-likelihood tree using IQ-TREE

   Main script:
   - scripts/09_run_mafft_iqtree.sh

   Outputs are under:
   - results/phylo/mafft_iqtree/{condition}/rep_001/

   Typical files:
   - alignment.fa
   - alignment_stats.tsv
   - inferred_tree.nwk
   - run.log
   - iqtree/ alignment outputs

3. mauve_iqtree
   Workflow:
   - split the all-tips FASTA into individual FASTA files
   - align whole genomes with progressiveMauve
   - convert XMFA output to a strict core alignment across all expected tips
   - summarize core alignment properties
   - infer a tree using IQ-TREE when the core alignment is usable

   Main script:
   - scripts/10_run_mauve_iqtree.sh

   Outputs are under:
   - results/phylo/mauve_iqtree/{condition}/rep_001/

   Typical files when successful:
   - split_fastas/
   - mauve/alignment.xmfa
   - mauve/guide_tree.nwk
   - core_alignment.fa
   - core_alignment_stats.tsv
   - xmfa_blocks.tsv
   - inferred_tree.nwk
   - run.log

   For high and very_high, this method was tested but did not produce valid final inferred trees in the scoring table. The strict core-alignment approach became unusable because many tips were represented only by gaps in the recovered core alignment. This is best treated as a method limitation at high divergence, not simply as an untested condition.


TREE SCORING AND VALIDATION

Inferred trees were scored against:

- data/true_trees/true_tree_16tips.nwk

Scoring script:

- scripts/12_score_trees.py

Main score outputs:

- results/tree_scores/tree_scores.tsv
- results/tree_scores/tree_validation.tsv
- results/tree_scores/tree_splits.tsv
- results/tree_scores/patristic_correlations.tsv

The scorer checks:

- whether each inferred tree exists
- whether the inferred tree has the expected 16 tips
- whether tips match the true tree
- number of branches
- negative branch lengths
- matching, missing, and extra unrooted splits
- Robinson-Foulds distance
- normalized Robinson-Foulds distance
- patristic distance correlation when branch lengths are usable

Interpretation of rep_001:

- All successful methods recovered the true topology perfectly at very_low and low mutation rates.
- MAFFT/IQ-TREE was strongest across the tested range, recovering the true tree perfectly through normal mutation and remaining relatively accurate at high mutation.
- Mash/BioNJ degraded substantially from normal upward.
- Mauve/IQ-TREE performed well through normal, but the strict core-alignment workflow did not produce usable trees for high or very_high.
- Very_high mutation was the strongest stress test: both Mash/BioNJ and MAFFT/IQ-TREE had clear topological error, and Mauve/IQ-TREE did not yield a scored tree.

WHAT HAS BEEN DEMONSTRATED SO FAR

The project has successfully demonstrated an end-to-end pilot workflow:

1. Simulate five mutation-rate conditions from a common Aevol setup.
2. Produce clean final FASTA files for 16 terminal species per condition.
3. Verify FASTA integrity and genome length distributions.
4. Run multiple phylogenetic inference strategies.
5. Score inferred trees against a known simulated tree.
6. Generate summary plots suitable for early results review.

The main biological/computational pattern in rep_001 is that tree recovery is easy at very_low and low mutation rates, begins to vary across methods at normal and high mutation rates, and becomes substantially worse or method-limited at very_high mutation rates.
